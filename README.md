# 🍳 めにゅらく！

期間を指定すると、AI（Claude）が**共働き家庭向けの時短献立**を作成してくれるWebアプリです。
作った献立はグループ（世帯）に保存され、**招待リンク**でパートナーや家族と共有できます。

- 公開URL: **https://menuraku.onrender.com**
- 要件・ロードマップ: [REQUIREMENTS.md](REQUIREMENTS.md)

## 主な機能
- **柔軟な日・食事指定**: 期間内で「作る日」と朝/昼/夕を選択（既定は平日の夕食）
- **時短条件・品数・人数・好み**: 1食あたりの調理時間の上限、主菜のみ／主菜＋副菜／主菜＋副菜＋汁物、苦手食材・要望テンプレ
- **AI献立作成**: 料理ごとに 役割・名前・説明・材料・作り方・調理時間の目安を生成
- **作り方なしの即時作成**: 料理カタログ（300品以上）から条件に合う献立をAIを使わずに組み立て。待ち時間なし・無料枠を消費しない
- **アレルギー除外**: 指定したアレルゲン（例:「甲殻類」）を含む料理を除外
- **野菜の使い回し**: 同じ野菜を複数の料理で使い、買い物の無駄を減らす（1回で使い切る野菜は対象外）
- **1食だけ作り直し／1品だけAIで差し替え**
- **買い物リスト**: 週ごとに材料を自動集約し、グループで共有。買い物完了をメンバーに通知。オフラインから復帰しても更新が失われない
- **べんり機能**: お気に入りレシピ／冷蔵庫・作り置き／カロリー・栄養計算／コラム／毎週おまかせ作成（プレミアム）
- **プッシュ通知（PWA）**: 今日の夕食リマインド、献立作成・買い物完了のお知らせなど
- **使い方ツアー**: 初回にスポットライトで案内（設定から何度でも呼び戻せる）

## 必要なもの
- [Node.js](https://nodejs.org/) 22 以上
- Claude API キー（[Anthropic Console](https://console.anthropic.com/) で取得）
- **Postgres データベース**（[Neon](https://neon.tech/) 推奨、または Supabase / ローカルPostgres）

## セットアップ
```bash
# 1. 依存パッケージをインストール
npm install

# 2. 環境変数を設定（.env.example をコピーして .env を作成し、値を入れる）
cp .env.example .env
#   .env に必須項目を設定:
#     ANTHROPIC_API_KEY=sk-ant-...
#     DATABASE_URL=postgresql://...@...neon.tech/neondb?sslmode=require

# 3. 起動（.env を自動読み込み。テーブルは初回起動時に自動作成）
npm start        # 開発中は npm run dev（ファイル変更で自動再起動）
```
ブラウザで **http://localhost:3000** を開いてください。

> `GOOGLE_CLIENT_ID` を設定しないローカル環境では、Googleログインが無効になり、ユーザー名＋パスワードで新規登録できます。

> 既存の SQLite（`data.db`）データを Postgres へ移行する場合は、`.env` に `DATABASE_URL` を設定した上で:
> ```bash
> npm run migrate:sqlite-to-pg
> ```

## デプロイ（Render）
本番は [Render](https://render.com/) にデプロイしています。
- リポジトリ直下の `render.yaml`（Blueprint）で構成（web / シンガポール / Starter プラン / `npm install`→`npm start` / healthcheck `/`）。`main` への push で自動再デプロイ。
- 秘密情報（`ANTHROPIC_API_KEY` / `DATABASE_URL` / `STRIPE_*` / `APP_BASE_URL` / `VAPID_*`）は Render のダッシュボードで設定。非秘密の既定値（`GOOGLE_CLIENT_ID`・`TEST_MODE`・無料枠・`PASSWORD_SIGNUP`・`SESSION_TTL_DAYS`・`NODE_VERSION`）は `render.yaml` に記載。
- Stripe Webhook は本番用にダッシュボードで `https://<公開URL>/api/billing/webhook` を登録（イベント: `checkout.session.completed` / `customer.subscription.updated` / `customer.subscription.deleted`）。その署名シークレットを `STRIPE_WEBHOOK_SECRET` に設定。ローカル検証は Stripe CLI の `stripe listen --forward-to localhost:3000/api/billing/webhook`。
- ★Stripe の本番キー・本番Webhook・本番の価格IDを入れ終えるまでは `TEST_MODE=1` のままにする。

## 課金（フリーミアム）
- 手動での献立入力・作り方なしの即時作成・買い物リスト・冷蔵庫・栄養表示・コラムは**無料**。
- **作り方つきのAI作成**は無料枠（既定 月**20食**）、**AIでの修正**は別枠（既定 月**10回**）。超えると月額サブスク。判定はサーバー側（`entitlements` テーブル＋事前チェック、超過は 402）。
- ひとりが契約すれば、同じグループのメンバーも追加料金なしでAI作成を使える。
- 月額 Price は `npm run stripe:setup <円>` で作成し、表示された `price_...` を `STRIPE_PRICE_ID` に設定。
- `TEST_MODE=1` の間は課金導線を止め、全機能を無料で開放。

## 使い方
1. **ログイン**（新規登録は「Googleで登録」。既存のユーザー名＋パスワードのアカウントもそのままログイン可能）
2. 初回は「グループ」を作成（あとで招待リンクでパートナーを招待できます）
3. 下部中央の ＋ から「作成」画面へ
4. 期間・作る日と食事・調理時間・品数・人数・好み（冷蔵庫の使い切り食材も選択可）を指定して作成
5. 生成された献立を確認。編集（鉛筆）・作り直し・買い物リストが使えます
6. 「ホーム」では**一覧（日ごと）**と**カレンダー**で献立を確認できます
   - 一覧: 日付ごとに各食事をコンパクト表示（1画面で約1週間分）。食事をタップで作り方、左の日付をタップで献立プラン（人数変更・削除）
   - カレンダー: 各マスに料理名を表示。日をタップでその日の献立
7. 下タブの「**買い物**」から買い物リストを開けます。週ごと（日曜〜土曜）にその週の全献立の材料を自動集約（上部の ‹ › で週を移動）。いちばん左に「日付」を表示。材料を手動追加する際に「いつ買うか」の日付も指定できます。買い終わったら完了にすると、メンバーへ通知されます
8. 下タブ構成: **ホーム／買い物／＋（作成）／べんり／設定**
   - 「**べんり**」: お気に入りレシピ・冷蔵庫・作り置き・カロリー・栄養計算・コラム・毎週おまかせ作成
   - 「**設定**」: グループ（メンバー招待・切替）・常備品リスト・食材の設定・プラン（課金）・通知・毎週おまかせ作成・アカウント・使い方ツアー

## 共有（グループ）
- 「設定」→「パートナーを招待」の**招待リンク**を LINE などで送るだけ。相手がリンクを開いてログインすると同じグループに参加できます（ユーザー名を指定して招待することも可能）
- リンクを開いても参加できなかったときは、「招待されたグループに参加」にリンクや招待コードを貼り付けて参加できます
- 複数のグループを切り替え可能。招待リンクは作り直す（無効化する）ことができます
- 以前のバージョン（共有URL方式）を使っていた場合、ログイン後に「以前のデータを引き継ぐ」ボタンが出ます（この端末に残る旧トークンを新アカウントに紐づけ）

> セキュリティ: パスワードは scrypt でハッシュ化して保存（平文保存なし）。API はすべてログインとメンバーシップで保護されています。
> 加えて、**セキュリティヘッダ（helmet/CSP・HSTS 等）**、**ログインセッションの有効期限**（既定30日 / `SESSION_TTL_DAYS`）、
> **レート制限**（ログイン・登録の総当たり抑止／AI生成の乱用・コスト暴走抑止 `AI_RATE_LIMIT_PER_HOUR`）を実装しています。

## 常備品リスト
- 「設定」で、家にいつもある食材（米・卵・玉ねぎなど）を登録できます
- 買い物リストでは、常備品に一致した材料を「**常備品（家にあるか確認）**」枠にまとめ、買い忘れ確認だけできるようにします（表記ゆれは正規化＋部分一致で吸収: 「鶏もも」で「鶏もも肉」もヒット。「卵」など1文字は完全一致のみなので「温泉卵」は通常リストに残ります）
- 常備品枠に入った品でも「**🛒 買う**」を押せば通常リストへ戻せます（例: 牛乳は常備だが低脂肪牛乳だけ買う。プランごとに記憶）

## 食材の設定
- 「設定」で食材ごとの扱いを登録すると、AI献立に反映されます
  - 🚫 **使わない食材**（アレルギー・苦手 → 絶対に使わない。作成のたびに自動で除外）
  - 🕓 **控えめにする食材**（買いにくい等 → できるだけ避けるが、たまにはOK）
  - 🥕 **定番の野菜**（毎週よく買うもの → 野菜の使い回しの軸にする）

## 料理を1品だけAIで差し替え
- レシピ画面の各料理にある「**✨ AIで変更**」から、「ただのサラダに」「具材だけ変えて」などと指示すると、その**1品だけ**をAIが作り直します（献立全体は作り直しません）

## レシピ画面での編集・並べ替え
- **役割の変更**: 料理の鉛筆（編集）から「役割」（主菜／副菜／汁物／主食／デザート）を変更できます
- **食事・日付の移動／入れ替え**: ホーム一覧で各食事の**⇅アイコン**をタップ → 上部に「**どの日付へ移動させますか？**」→ **行をタップ＝同じ食事枠へ**移動/入れ替え、**別の食事をタップ＝その食事と入れ替え**（朝/昼/夕の選択も可）→ 確認。PCでは**ドラッグ&ドロップ**でも可能。日付を移動すると、**買い物リストの該当材料も同じ週内で日付が付け替わり（「○/○から移動」の注釈付き）、買い物済みチェックはそのまま維持**されます

## コラム
- `content/columns/` に `.md` を1記事1ファイルで置くと、アプリの「コラム」に出ます（ビルド不要）。書き方は [content/columns/README.md](content/columns/README.md) を参照

## 仕組み
- `server.js` … Express サーバー ＋ Postgres（テーブルは起動時に自動作成）。APIキーはサーバー側だけで保持。
  Claude の forced tool use で構造化した献立データを生成します。モデルは既定で `claude-haiku-4-5`（`GEN_MODEL` / `GEN_MODEL_SINGLE` で変更可）。
- `public/index.html` … 画面とロジックを含むフロントエンド（1ファイル）。`public/sw.js` と `manifest.webmanifest` で PWA・プッシュ通知に対応。
- `catalog.js` / `data/dish-catalog.json` … 料理カタログ（即時作成・候補の絞り込みに使用）
- `allergens.js` / `produce.js` / `nutrition.js` / `nutrition-advice.js` / `columns.js` … アレルゲン判定・野菜の使い回し・栄養計算・栄養アドバイス・コラム読み込み
- `scripts/` … カタログの点検・補強（`npm run catalog:check` / `catalog:fix` / `catalog:enrich` / `catalog:view`）、コラムの下見（`npm run columns`）、Stripe の Price 作成、SQLite→Postgres 移行
- 材料は `{名前, 分量}` の構造化で保存（買い物リストの集約・常備品の振り分けに再利用）。
