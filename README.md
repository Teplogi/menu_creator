# 🍳 めにゅらく！

期間を指定すると、AI（Claude）が**共働き家庭向けの時短献立**を作成してくれるWebアプリです。
作った献立は保存でき、**世帯コード／共有URL**で家族と共有できます。

> 対応フェーズ: **Phase 1（MVP）**。詳しい要件・ロードマップは [REQUIREMENTS.md](REQUIREMENTS.md) を参照。

## 主な機能（Phase 1）
- **柔軟な日・食事指定**: 期間内で「作る日」と朝/昼/夕を選択（既定は平日の夕食）
- **時短条件**: 1食あたりの調理時間の上限を指定
- **品数の指定**: 主菜のみ / 主菜＋副菜 / 主菜＋副菜＋汁物
- 人数・苦手食材・好みの指定
- 献立生成（料理ごとに 役割・名前・説明・材料・作り方・調理時間の目安）
- **世帯コード／共有URL** による複数人共有（ログイン不要）
- プランの**保存**と**履歴一覧**
- **1食だけ作り直し**

## 必要なもの
- [Node.js](https://nodejs.org/) 22 以上
- Claude API キー（[Anthropic Console](https://console.anthropic.com/) で取得）
- **Postgres データベース**（[Neon](https://neon.tech/) 推奨、または Supabase / ローカルPostgres）

## セットアップ
```bash
# 1. 依存パッケージをインストール
npm install

# 2. 環境変数を設定（.env.example をコピーして .env を作成し、値を入れる）
cp .env.example .env
#   .env に必須項目を設定:
#     ANTHROPIC_API_KEY=sk-ant-...
#     DATABASE_URL=postgresql://...@...neon.tech/neondb?sslmode=require

# 3. 起動（.env を自動読み込み。テーブルは初回起動時に自動作成）
npm start
```
ブラウザで **http://localhost:3000** を開いてください。

> 既存の SQLite（`data.db`）データを Postgres へ移行する場合は、`.env` に `DATABASE_URL` を設定した上で:
> ```bash
> npm run migrate:sqlite-to-pg
> ```

## 使い方
1. **アカウント登録／ログイン**（ユーザー名＋パスワード）
2. 初回は「世帯」を作成（あとで家族を招待できます）
3. 下部中央の ＋ から「作成」画面へ
4. 期間・作る日と食事・調理時間・品数・人数・好みを指定して「献立を作成する」
5. 生成された献立を確認。編集（鉛筆）・作り直し・買い物リストが使えます
6. 「ホーム」では**一覧（日ごと）**と**カレンダー**で献立を確認できます
   - 一覧: 日付ごとに各食事をコンパクト表示（1画面で約1週間分）。食事をタップで作り方、左の日付をタップで献立プラン（人数変更・削除）
   - カレンダー: 各マスに料理名を表示。日をタップでその日の献立
7. 下タブの「**買い物**」から買い物リストを開けます。買い物リストは**週ごと（日曜〜土曜）**にその週の全献立の材料を自動集約（上部の ‹ › で週を移動）。材料を手動追加する際に「いつ買うか」の日付も指定できます
8. 下タブ構成: **ホーム／買い物／＋（作成）／べんり／設定**。「**設定**」に世帯（メンバー招待・切替）・常備品リスト・アカウントを集約。「**べんり**」は今後の便利機能（カロリー計算など）を予告する近日公開ページ

## 共有（共同編集者）
- 右上または下部の「世帯」→「共同編集者を招待」で、**相手のユーザー名**を入力すると同じ世帯を一緒に使えます
- 複数の世帯を切り替え可能。ログアウトも同画面から
- 以前のバージョン（共有URL方式）を使っていた場合、ログイン後の世帯設定画面に「以前のデータを引き継ぐ」ボタンが出ます（この端末に残る旧トークンを新アカウントに紐づけ）

> セキュリティ: パスワードは scrypt でハッシュ化して保存（平文保存なし）。API はすべてログインとメンバーシップで保護されています。

## 仕組み
- `server.js` … Express サーバー ＋ SQLite（`data.db` を自動生成）。APIキーはサーバー側だけで保持。
  Claude の forced tool use で構造化した献立データを生成します。モデルは `claude-opus-4-8`。
- `public/index.html` … 画面（はじめに／ホーム／作成／詳細／共有）とロジックを含むフロントエンド。
- データ保存: SQLite。`households` / `meal_plans` テーブル。材料は `{名前, 分量}` の構造化で保存
  （将来の買い物リスト集約・スーパー食材の振り分けに再利用するため）。

## データについて
- `data.db` は初回起動時に自動作成されます（Gitには含めない想定）。
- 共有トークンを知っている人は誰でもその世帯の献立を閲覧・編集できます（緩い共有モデル）。

## 常備品リスト（Phase 4 の第一歩）
- 「世帯」画面で、家にいつもある食材（米・卵・玉ねぎなど）を登録できます
- 買い物リストでは、常備品に一致した材料を「**常備品（家にあるか確認）**」枠にまとめ、買い忘れ確認だけできるようにします（表記ゆれは正規化＋部分一致で吸収: 「鶏もも」で「鶏もも肉」もヒット。「卵」など1文字は完全一致のみなので「温泉卵」は通常リストに残ります）
- 常備品枠に入った品でも「**🛒 買う**」を押せば通常リストへ戻せます（例: 牛乳は常備だが低脂肪牛乳だけ買う。プランごとに記憶）

## 料理を1品だけAIで差し替え（機能5）
- レシピ画面の各料理にある「**✨ AIで変更**」から、「ただのサラダに」「具材だけ変えて」などと指示すると、その**1品だけ**をAIが作り直します（献立全体は作り直しません）

## レシピ画面での編集・並べ替え
- **役割の変更**: 料理の鉛筆（編集）から「役割」（主菜／副菜／汁物／主食／デザート）を変更できます
- **食事・日付の移動／入れ替え**: ホーム一覧で各食事の**⇅アイコン**をタップ → 上部に「**どの日付へ移動させますか？**」→ **行をタップ＝同じ食事枠へ**移動/入れ替え、**別の食事をタップ＝その食事と入れ替え**（朝/昼/夕の選択も可）→ 確認。PCでは**ドラッグ&ドロップ**でも可能。日付を移動すると、**買い物リストの該当材料も同じ週内で日付が付け替わり（「○/○から移動」の注釈付き）、買い物済みチェックはそのまま維持**されます
